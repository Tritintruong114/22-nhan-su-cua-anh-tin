## GA4 tracking format for Agent apps - multi-channel sales assistant (2026-09-29)

- For Agent app tracking, start from the product story and funnel, not raw clicks. Break a feature into: user enters surface -> starts step -> key business action starts/completes/fails -> optional proof/engagement action -> final conversion. Track only events that answer product/business questions.
- Event naming pattern: `{screen}_{object}_{action}_{status}` in `snake_case`. Every event for a screen/feature shares the same screen prefix. Example: all onboarding events start with `onboarding_`.
- Use square-bracket placeholders in planning docs when an event name substitutes a dimension value: `onboarding_[channel]_connect_completed` means concrete events like `onboarding_facebook_connect_completed`, `onboarding_zalo_connect_completed`, or `onboarding_web_connect_completed`. `[...]` is a planning placeholder, not literal text.
- Use `Params sent` for fields developers send to GA4 with the event, such as `channel`, `source`, `step_id`, `reason`, `error_code`. Use `Report by` for the field the team will group/filter reports by, such as `channel` to compare Facebook/Zalo/Web.
- `Dimension value` is the concrete value for a report field or placeholder, for example `channel = facebook`, `source = sheet`, or `step_id = channel_connect`.
- Current onboarding flow for the multi-channel sales assistant: onboarding/checklist view -> Step 1 channel connect -> Step 2 product setup -> optional test chat -> Go live button appears only after Step 1 + Step 2 are done -> Go live modal view -> confirm click -> completed/failed.
- Do not use `missing_channel` or `missing_product` as Go live failure reasons when the UI hides the Go live button until prerequisites are satisfied. Valid Go live failure reasons are post-confirm errors such as `runtime_write_error`, `persona_error`, or `audit_error`.
- Useful onboarding event examples: `onboarding_[step_id]_start`, `onboarding_[step_id]_completed`, `onboarding_[channel]_connect_started`, `onboarding_[channel]_connect_completed`, `onboarding_[channel]_connect_failed`, `onboarding_product_setup_[source]_started`, `onboarding_product_setup_[source]_completed`, `onboarding_product_setup_[source]_failed`, `onboarding_test_chat_opened`, `onboarding_test_chat_message_sent`, `onboarding_go_live_clicked`, `onboarding_go_live_modal_view`, `onboarding_go_live_confirm_clicked`, `onboarding_go_live_completed`, `onboarding_go_live_failed`.

## Feature breakdown for Agent apps - sales assistant multi-channel (2026-09-29)

- After onboarding, break the multi-channel sales assistant into trackable product surfaces: Conversations, Orders, Products, Store channels, Store payment, Store notifications, Staff/Training, Run switch, Sandbox/Test chat, and Audit/Review.
- Prioritize Conversations after Onboarding because it proves the core operating value: customer message arrives, agent replies, owner can take over, order can be created, and corrections can train the AI staff.
- For each feature surface, apply the same funnel shape: surface view -> start/use core action -> success/failure -> optional correction/review/training moment -> business outcome.
- Keep tracking tied to Agent app behavior, not generic dashboard interactions. Good events expose whether the agent is doing useful work, where trust gates appear, where human approval happens, and which actions lead to go-live, response, order, or training outcomes.

## GA4 Conversations tracking concept - sales assistant multi-channel (2026-09-29)

- After onboarding and Go live, the next activation story is: user goes to their Fanpage/Zalo/Web to send a real test message -> backend receives the message -> AI staff replies -> user may return to the Conversations dashboard to inspect the thread or take over.
- Keep the first Conversations tab simple: do not track order creation in this phase. Core events are `conversations_view`, `conversations_[channel]_message_received`, `conversations_[channel]_ai_reply_sent`, `conversations_[channel]_ai_reply_failed`, `conversations_thread_opened`, and `conversations_thread_takeover_clicked`.
- Treat message received / AI reply sent / AI reply failed as likely server-side webhook/backend events. Treat `conversations_view`, `conversations_thread_opened`, and `conversations_thread_takeover_clicked` as client-side dashboard events.
- Metrics this should answer: how many shops test with a real message after Go live, which channel is tested most, whether AI replies successfully, how often AI reply fails, how many users return to inspect the conversation, and how often owners need to take over.
- For the Google Sheet tracking spec, keep all feature tabs visually consistent with `Onboarding`: header `#1F2937`, white bold centered text, frozen first row, wrapped cells, `Event name` + `Dimension value` columns in light `#F8FAFC` with monospace font, other body columns in `#E5E5E5`, light borders, and dimension/reference rows at the bottom.
