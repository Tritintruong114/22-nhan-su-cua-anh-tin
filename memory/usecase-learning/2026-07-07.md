# Use Case Learning — 2026-07-07

## TL;DR

- Hôm nay bài học mạnh nhất không phải là thêm feature, mà là **tách rõ agent product/workspace với toolchain/plugin**. Usecase Agent không nên bị hiểu là bản copy của Use-Case Factory; nó là một agent sản phẩm dùng Use-Case Factory như tooling nội bộ.
- Với agent app cho non-tech user, “xài được” gồm 3 cổng: **runtime đăng ký được**, **artifact publish/share được**, và **state/CTA reach được qua flow thật**. Thiếu một cổng thì user vẫn thấy sản phẩm hỏng dù logic agent đúng.
- `ws-agent-email` tiếp tục củng cố bài học: bug UI nhỏ như font fallback, blank page, nav guard sai là **trust bug**, vì non-tech user đánh giá độ an toàn/đáng tin trước khi hiểu agent loop.

## Strongest pattern learned today

**Workspace-as-product, toolchain-as-internal-engine.**

Một agent chuyên dụng cần có repo/workspace/output contract riêng, còn skill/plugin/factory chỉ là engine. Nếu trộn hai lớp này, user sẽ không biết:

- artifact nào là deliverable thật,
- repo nào để publish/share,
- agent nào đang chạy trong OpenClaw,
- lỗi nằm ở product workflow hay toolchain.

Pattern đúng cho Usecase Agent:

1. Agent workspace/product: `/home/node/.openclaw/workspace-usecase-agent`
2. Internal tooling: `_tooling/usecase-factory/`
3. Outputs: `runs/ws-<slug>/`
4. Sharing: GitHub/Vercel readiness gate
5. Runtime identity: `usecase-agent`, display `Usecase Agent`

## Use-case improvement notes

### Usecase Agent

- **Core problem:** Trí cần một agent chuyên làm use case: từ idea thô → research → decision pack → agent domain spec → screen brief/mockup/prototype → link share được.
- **Target user:** Trí/founder/operator non-technical hoặc semi-technical muốn đánh giá idea agent nhanh, không muốn đọc cả đống file rời.
- **Domain layers:** idea intake, evidence/dossier, decision gate, agent domain spec, screen brief, mockup/prototype, publish package.
- **Meta layers:** source-of-truth, trust/evidence labels, publish readiness, runtime registration, output contract, handoff clarity.
- **Agent decision logic:** không nên polish idea quá sớm; phải ép qua pain/buyer/workaround/agent fit/OpenClaw advantage/verdict trước khi vẽ UI.
- **Core loop:** Intake → Evidence → Decision → Agentize domain → Project to UI → Publish/share → Learn from feedback.
- **OpenClaw advantage:** agent có workspace riêng, memory, cron learning, shell/git/Vercel checks, skills vendored, và có thể chạy như subagent đúng runtime.

### ws-agent-email

- **Core problem:** không bỏ sót tiền/trách nhiệm trong email; không phải inbox summary.
- **Product learning mới:** navigation guard và deploy/font issues phải nằm trong acceptance criteria, không chỉ “frontend cleanup”. Nếu CTA không reach được thì agent loop không tồn tại với user.
- **Trust layer:** Activity Log, Operating Memory, onboarding consent, and reachable state matrix vẫn là các lớp làm user tin agent.

## Non-tech usability notes

- Non-tech user không quan tâm “đã tạo local files”; họ cần **link xem được** và một `00-START-HERE.md` đọc dưới 3 phút.
- Với prototype, user không test bằng cách đọc code hoặc gọi `App.nav()`. Họ click CTA. Vì vậy cần reachability gate theo hành động thật.
- Một agent chuyên dụng phải hiện ra và edit/run được trong OpenClaw runtime; nếu chỉ là folder local thì chưa phải sản phẩm hoạt động.
- Với UI agent app, font/blank page/nav broken không phải lỗi nhỏ. Nó làm user nghi agent thiếu kiểm soát, từ đó giảm trust cho những hành động nhạy cảm như đọc email hoặc draft gửi khách.

## OpenClaw / Claude terminal leverage

- OpenClaw mạnh ở chỗ biến quy trình agent thành **operational workspace**: repo riêng, memory, cron learning, subagent, git state, Vercel/GitHub gate.
- Claude/Codex-terminal style workflow mạnh cho build/debug/publish, nhưng cần source-of-truth rõ: spec/mockup trước prototype, workspace product trước tooling repo.
- Use-Case Factory đang có runtime kép: Claude plugin và OpenClaw skill. Bài học là cùng một engine có thể phục vụ nhiều môi trường, nhưng output contract phải giữ ổn định.

## Reusable agent design patterns

1. **Product Workspace vs Toolchain Boundary**
   - Agent product có workspace, runs, decisions, public/deployments riêng.
   - Toolchain/plugin nằm trong `_tooling/` hoặc repo nguồn riêng.
   - Không publish deliverable từ toolchain repo nếu sản phẩm là agent workspace.

2. **Publish Readiness Gate**
   - Mỗi run kiểm tra GitHub remote/auth, Vercel login, artifact path.
   - “Done” phải gồm local path + commit + GitHub URL nếu có + Vercel URL nếu có.

3. **State Reachability Gate**
   - Mỗi key state/CTA trong brief/mockup phải là `reachable / demo-only / missing`.
   - Reachable nghĩa là user đi tới được bằng flow thật hoặc simulated agent event rõ ràng.

4. **Runtime Registration Gate**
   - Với agent mới, folder + config chưa đủ. Cần verify runtime list/health và smoke test response.
   - Nếu UI chưa edit được, phân biệt lỗi registration/runtime visibility với lỗi product concept.

5. **Trust Bug Classification**
   - Blank page, wrong font, broken CSS bundle, stale deploy, nav guard sai đều là trust bugs trong agent app.
   - Acceptance criteria nên có visual/load/navigation verification sau deploy.

## Risks / weak spots

- `ws-agent-email` đang có working tree modified và branch ahead; nếu không commit/push rõ, future agent dễ nhầm source vs deployed artifact.
- `workspace-usecase-agent` đã có remote theo git status, nhưng prior note nói từng thiếu remote; cần publish readiness script là nguồn kiểm tra mới nhất trước mỗi run.
- Usecase Agent dễ bị lẫn với Use-Case Factory nếu tên folder/tooling không được nhắc lại trong handoff.
- Cron learning chỉ hữu ích nếu lesson được distill ngắn; không nên đổ nguyên daily logs vào MEMORY.

## Memory candidates

Durable enough to keep:

- Do not confuse toolchain source with the agent’s product workspace. A dedicated agent should own its outputs, publishing path, decisions, and runtime identity; vendored skills/plugins are only internal engines.
- For completed use-case work, local artifacts are insufficient for non-tech review. Require a publish readiness gate: commit, GitHub URL when available, Vercel/preview URL for visual artifacts, and clear missing setup if unavailable.
- New agent setup needs a runtime registration gate: verify OpenClaw can list/run the agent and smoke-test a response, not just create folders/config.
