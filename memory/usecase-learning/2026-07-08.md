# Use Case Learning — 2026-07-08

## TL;DR

Hôm nay bài học chính đến từ `ws-agent-email` và `usecase-factory`: một agent app cho non-tech user không chỉ cần đúng logic nghiệp vụ, mà còn phải **dịch logic đó thành ngôn ngữ người dùng tin được**. Các thay đổi gần đây trong prototype đang đi đúng hướng: giảm jargon như `draft`, `thread`, `contact`, `export`, `corrections`; tăng nhãn tiếng Việt rõ nghĩa như “bản nháp”, “cuộc hội thoại”, “người gửi”, “tải về”, “lịch sử sửa chữa”.

Insight lớn: **agent càng phức tạp ở backend thì UI càng phải đơn giản, cụ thể, và có bằng chứng giải thích được.**

## Strongest pattern learned today

**Jargon removal is not copy polish; it is trust design.**

Với sản phẩm agent email cho solopreneur, người dùng không mua “AI phân loại thread”. Họ mua cảm giác: “agent đã lọc hộ, chỉ còn vài việc tôi cần quyết”. Vì vậy, từng nhãn UI phải chuyển từ ngôn ngữ kỹ thuật sang ngôn ngữ trách nhiệm:

- `thread` → “cuộc hội thoại”
- `draft` → “bản nháp”
- `contact` → “người gửi” / “khách”
- `digest` → “tổng hợp sáng”
- `export` → “tải về”
- `corrections` → “lịch sử sửa chữa”
- `bounce/NDR` → “mail bị trả lại”

Đây là lớp non-tech usability nằm giữa domain spec và prototype: cùng một logic agent, nhưng nếu label sai thì user nghĩ đây là công cụ kỹ thuật, không phải trợ lý đáng tin.

## Use-case improvement notes

### Email Revenue Follow-through Agent

- **Core problem:** solopreneur bỏ sót tiền/cơ hội vì email nằm rải rác; agent được thuê để phát hiện, ưu tiên, chuẩn bị hành động, và theo dõi đến khi có kết quả.
- **Target user:** non-technical hoặc semi-technical solopreneur/freelancer/consultant, dùng email làm sales pipeline; họ cần ngôn ngữ “việc cần xử lý”, không cần thấy ontology backend.
- **Domain layers:** Thread/Cuộc hội thoại, Draft/Bản nháp, Follow-up, Reply classification, Queue bucket, Cadence, Exclude, Operating Memory.
- **Meta layers:** approval bắt buộc, audit log giải thích vì sao agent làm vậy, Operating Memory minh bạch, data/privacy controls, state reachability.
- **Agent decision logic:** detect → classify → prioritize → prepare draft → ask human approval → track reply → update memory/playbook.
- **Core loop:** “80 email đã lọc → 9 việc cần anh xử lý” vẫn là câu sản phẩm mạnh nhất. Prototype/copy nên bám câu này liên tục.

### Usecase Factory

- Factory đang có contract tốt: Decision Pack, `00-START-HERE.md`, `01-PRODUCT-MAP.md`, `Agent-Domain-Spec.md`, `screens-brief.md`, prototype artifact.
- Bài học bổ sung: trong pipeline nên có một **Plain-language Review Gate** trước khi render/prototype: kiểm tra mọi label, CTA, state, bucket có đang dùng ngôn ngữ người mua/người dùng không.
- Với non-tech buyer, “agent-domain spec đúng” chưa đủ; cần map rõ thành copy và UI primitives dễ hiểu.

## Non-tech usability notes

- Non-tech user không nên bị ép học từ vựng backend. UI nên nói theo kết quả họ cần làm: “Cần bạn trả lời”, “Đã có reply”, “Cần follow-up”, “Có thể bỏ qua”, “Mail bị trả lại”.
- Audit log nên giải thích bằng cấu trúc: **Agent suy luận → Tín hiệu phân tích → Tác động Operating Memory**. Đây là cách biến agent black-box thành một đồng nghiệp có thể kiểm tra.
- Icon + label rõ nghĩa giúp giảm cognitive load, nhưng icon không thay thế được copy. Emoji/icon nên bổ trợ cho trạng thái, không biến UI thành trò chơi.
- Privacy/destructive settings cần tiếng Việt cực rõ: “Không thể hoàn tác”, “Xoá toàn bộ & ngắt kết nối”, “Tải file JSON: hội thoại, bộ nhớ, cài đặt”.

## Reusable agent design patterns

1. **Plain-language Gate**
   - Trước khi prototype được xem là review-ready, kiểm tra tất cả label/CTA/state có dùng ngôn ngữ của người dùng không.
   - Fail nếu còn nhiều từ backend: thread, draft, NDR, correction, export, webhook, classifier, confidence mà không được dịch/giải thích.

2. **Responsibility Queue Pattern**
   - Agent không show toàn bộ inbox/task list.
   - Agent show phần trách nhiệm còn lại của human sau khi đã xử lý/lọc/phân loại.
   - Copy mẫu: “X đã xử lý / Y việc cần anh quyết hôm nay”.

3. **Explainable Event Row Pattern**
   - Mỗi action quan trọng của agent có row audit: what happened, why, signals, state change, memory impact.
   - Dùng cho trust, debugging, và training loop.

4. **Operating Memory as Control Surface**
   - Memory không chỉ là backend hidden state.
   - Nó cần UI để user xem/sửa/bác/xác nhận: voice, avoided phrases, contact priority, correction patterns, cadence suggestions.

## Risks / weak spots

- Nếu prototype chỉ đổi copy mà chưa kiểm state reachability, user vẫn có thể tin nhầm là flow hoàn chỉnh. Cần giữ reachability matrix.
- Nếu copy quá “đời thường” nhưng mất trace sang domain spec, builder có thể khó implement. Cần song song: label người dùng + field/backend rõ trong spec.
- Sản phẩm email agent dễ trượt về “inbox assistant” nếu dashboard/queue không luôn nhấn mạnh revenue/responsibility/follow-through.
