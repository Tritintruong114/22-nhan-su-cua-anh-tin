## Strongest pattern learned today

**Prototype is not the source of truth; it is a behavior test of the source of truth.**

Với agent app, thứ cần đúng trước là:

1. Core problem: user thuê agent để giải việc đau nào.
2. Agent Domain Spec: object, lifecycle, intent, decision policy, approval, guardrail, memory.
3. Screen brief/mockup: state, CTA, copy, trust/evidence surface.
4. Prototype: làm các state quan trọng reachable qua hành động thật để test loop.

Nếu prototype chỉ đẹp hoặc có demo toggle ẩn, nó không test được agent loop. Với non-tech user, prototype phải trả lời: “tôi bấm gì, agent làm gì, khi nào nó dừng để hỏi tôi, vì sao tôi tin nó?”

## Non-tech usability notes

- Non-tech user không mua “agent phân loại intent”; họ mua “chỉ còn 9 việc cần anh xử lý hôm nay”.
- Ngôn ngữ UI nên dùng việc/nguy cơ/hành động: “Cần bạn trả lời”, “Mail bị trả lại”, “Đã có reply — xác nhận đóng”, “Cần follow-up”, “Có thể bỏ qua”.
- Onboarding phải là trust moment, không phải form cấu hình: 1 câu risk intent → Gmail consent → scan → Risk Profile Draft → confirm/correct → Responsibility Queue.
- Evidence mặc định nên là Level B: pattern + subject/snippet che nhẹ + high-level signals; Level C/full evidence chỉ khi click sâu.
- Audit coverage là bắt buộc nếu claim “80 email đã xử lý”. User cần thấy phần còn lại được bỏ qua vì sao.

## Reusable agent design patterns

1. **Decision Pack entry point**
   - `00-START-HERE.md` cho verdict/summary/routing.
   - `01-PRODUCT-MAP.md` cho pain → user → workflow → agent job → moat.
   - `Agent-Domain-Spec.md` cho nghiệp vụ agent.
   - `screens-brief.md` + mockup cho review state/CTA.

2. **State reachability gate**
   - Mockup đủ state chưa đủ.
   - Prototype phải cho state chính xuất hiện qua hành động thật hoặc agent event giả lập rõ ràng.

3. **Responsibility Queue pattern**
   - Raw input lớn → agent work invisible-but-auditable → small human decision queue.
   - Value nằm ở reduction có bằng chứng, không nằm ở summary dài.

4. **Operating Memory over fine-tuning**
   - Correction/outcome trở thành rule, cadence, approved example, contact preference, playbook update.
   - Đây là company asset dễ giải thích hơn “AI tự học”.

5. **Evidence ladder**
   - A pattern-only: nhẹ nhưng dễ thiếu tin.
   - B masked examples: default tốt.
   - C full evidence: chỉ khi user yêu cầu.

## Risks / weak spots

- Prototype generator có thể tạo preview “đẹp” nhưng sai product contract nếu không ép theo mockup/brief.
- Nếu `to-prototype` không kiểm tra reachability, team sẽ tưởng flow đã đủ trong khi các state rủi ro như error, bounce, needs-reply, confirm-close không bao giờ được test.
- Nếu Decision Pack quá nhiều file mà `00-START-HERE.md` không thật sắc, non-tech founder sẽ lạc trong tài liệu.
- Nếu agent app nói bằng thuật ngữ backend/model, buyer không cảm được ROI.
- Nếu claim “processed X emails” mà không có coverage/evidence, trust gãy.
