- Trí đang nghiên cứu repo `usecase-factory` (GitHub: Tritintruong114/usecase-factory) tạo pipeline idea -> research -> evidence dossier -> decision gate -> screen brief -> ASCII/wireframe -> HTML handoff. Nhận định đã gửi: repo mạnh ở use-case discovery và screen pipeline, nhưng thiếu tầng giữa MVP Core Loop và Screen Brief.
- Khái niệm quan trọng đã thống nhất khi phản biện sản phẩm AI Agent: `screen brief = app surface/UI projection`; `nghiệp vụ agent = domain + decision system`. Nghiệp vụ agent mô tả agent thấy object nào, hiểu state/intent nào, áp rule nào để quyết định action, cần approval ra sao, khi nào im lặng, xử lý uncertainty thế nào, và học từ feedback ra sao.
- Phân biệt cần nhớ: `nghiệp vụ business` kiểu BA/outsource mô tả quy trình con người/doanh nghiệp, form, rule, phòng ban, dữ liệu; còn `nghiệp vụ agent` biến quy trình đó thành hệ quyết định có autonomy, confidence/uncertainty, permissions, guardrails, feedback loop, và trust recovery.
- Đề xuất cho `usecase-factory`: thêm skill/plugin `agent-domain-spec` đặt giữa `run`/MVP coreloop và `grill-to-brief`. Output nên là `Agent-Domain-Spec.md` gồm domain thesis, core objects, lifecycle/state machine, intent taxonomy, eligibility rules, decision policy, priority scoring, confidence/uncertainty, approval policy, draft/action policy, anti-abuse guardrails, learning loop, background jobs, metrics.
- Đề xuất thêm 2 agent cho plugin: `domain-modeler-agent` để trích core objects/lifecycle/taxonomy/decision points từ research + MVP core loop; `agent-logic-reviewer` để adversarial review decision logic, over-automation, unclear states, missing approvals, trust-killing edge cases, spam risk, và mismatch giữa UI với domain spec.

Điểm thiếu là Agent Domain Spec: thread lifecycle, follow-up eligibility, intent taxonomy, priority scoring, confidence, correction loop, draft policy, anti-spam rules, data boundaries, background jobs, metrics.
