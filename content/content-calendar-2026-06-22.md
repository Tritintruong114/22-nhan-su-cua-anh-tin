Format: Short thread, 6 tweets
Topic: AI Agent is not a chatbot
Post:
1/ "AI Agent" is getting abused as a label.

A chatbot answers.
An automation follows rules.
An agent observes, reasons, calls tools, and changes state.

That last part is why the risk profile is different.

2/ If your agent can access CRM, email, docs, calendar, code, or finance tools, the question is no longer "is the answer good?"

It becomes:
What can it do?
Who approved it?
Can we replay the decision?

3/ My simple test:
If it cannot take a useful action, it is probably a chatbot.
If it can take action but has no logs, limits, or approvals, it is probably a liability.

4/ The winning AI agent teams in 2026 will not be the ones with the fanciest prompts.

They will be the ones with:
tool boundaries
memory discipline
human approval
rollback
observability

5/ Vietnam has a chance to skip the messy phase.

Do not copy "auto everything" content blindly.
Build operators, not toys.

6/ Useful framing:
Chatbot = talk
Workflow = repeat
Agent = operate
Governed agent = operate safely

### Tue 2026-06-23, 11:30 ICT

Format: Text post
Topic: AI Agent for Vietnamese SMBs
Post:
Most Vietnamese SMEs should not start with a "fully autonomous AI agent."

They should start with one boring workflow that already happens every day:

- classify new leads
- summarize customer tickets
- extract invoice data
- draft follow-up emails
- update CRM fields
- prepare daily reports

Then add three controls:

1. The agent can only access the minimum tools it needs.
2. Expensive or customer-facing actions require human approval.
3. Every action is logged so the business can inspect what happened.

This is less glamorous than a demo where an agent does everything.
It is also much closer to production.

For Vietnam, the opportunity is not "replace people with AI."
The opportunity is to turn repeated manual work into controlled operating loops.

CTA: What workflow in your team repeats every week but still needs human judgment?

Before connecting an AI agent to company systems, ask these 10 questions:

1. What exact job is the agent responsible for?
2. Which data can it read?
3. Which systems can it write to?
4. Which actions require human approval?
5. How do we stop it quickly?
6. Where are tool calls logged?
7. How do we detect prompt injection?
8. What is the fallback when the model is uncertain?
9. Who owns the workflow after launch?
10. What metric proves it is working?

The companies that win with AI agents will not be the ones that automate the most.
They will be the ones that automate the clearest workflows with the strongest operating discipline.

### Fri 2026-06-26, 11:30 ICT

Format: Text post
Topic: Why "proof over promise" matters for AI agents
Post:
The AI agent conversation is maturing.

In 2024, the question was: "Can this model answer well?"
In 2025, it became: "Can this agent use tools?"
In 2026, the serious question is: "Can this system be trusted in production?"

For a business, proof means:

- fewer manual hours
- faster response time
- lower error rate
- clear approval paths
- auditable logs
- stable cost per workflow

If an AI agent cannot show its work, it will struggle in finance, HR, legal, support, healthcare, and any regulated workflow.

That is why I care less about viral demos and more about harnesses, permissions, logs, and rollback.

AI agents are no longer just a prompt engineering topic.
They are becoming an operations design topic.

CTA: If you are evaluating an AI agent vendor, ask them to show the log before they show the demo.
